## 2. Upstream projects

### 2.1 `girafic/penpot-converter` — no license

Evidence:

- GitHub API metadata: `"license": null`.
- No `LICENSE`, `COPYING`, or `NOTICE` file at the repository root.
- `package.json` has `"private": true` and **no** `license` field.
- Its README states that `@ppc/core` is upstream exporter code "taken 1:1" with four
  patches, and that the converter is "a port of penpot/penpot-exporter-figma-plugin".

Legal consequence: with no license, the default is **all rights reserved**. There is no
permission to copy, modify, or redistribute the code, tests, or documentation. The fact
that parts of it are derived from MPL-2.0 code does not grant us a license from the
repository author, and the repository's own redistribution may not satisfy MPL notice
requirements. We treat the entire repository as **reference-only**.

What we may use:

- Facts about file formats and observed behavior.
- General ideas and algorithms (not patent-cleared; see §8).
- Public statements about limitations, used as research leads.

What we may not use:

- Source code, tests, build scripts, comments, or documentation text copied verbatim or
  with cosmetic changes.
- Its fixtures or generated outputs, unless their own license is established.

### 2.2 `penpot/penpot-exporter-figma-plugin` — MPL-2.0

Evidence: `LICENSE` is the Mozilla Public License 2.0; `package.json` declares
`"license": "MPL2.0"`.

MPL-2.0 in brief (not a substitute for the text):

- It is **file-level** copyleft. MPL-covered files, and modifications of them, must be
  made available in source form under MPL-2.0.
- You may combine MPL-covered files with other code in a larger work, provided the MPL
  files remain MPL and their notices are preserved.
- Distributing modified MPL files requires source disclosure for those files.
- There is a patent grant from contributors.
- No trademark license is granted.

Translating an MPL-covered file into Rust is a modification/derivative of that file in the
ordinary engineering sense, so the resulting file would carry MPL obligations. Our default
is therefore **no translation, no copying**. If a future contributor wants to port a small
MPL file, that file must be isolated, marked MPL-2.0, and its source made available; this
must be an explicit ADR, not a drive-by change.

### 2.3 `penpot/penpot` — MPL-2.0

Same obligations as §2.2. We read the schemas, importer, and renderer to establish format
facts. No code is copied.

The generated `.penpot` probe used for format observation is **data output**, not a copy of
the library. It is kept outside the repository and is not distributed. Our own golden
fixtures will be generated by our own writer.

### 2.4 `@penpot/library` — MPL-2.0

Same obligations. We used it to generate a probe archive for observation; we do not depend
on it at runtime and do not copy its code.

### 2.5 `openfig-core` — MIT (metadata), no license file

Evidence: `package.json` declares `"license": "MIT"`. There is **no LICENSE file** in the
repository at the studied commit. That is a packaging gap, not a change of terms: the
package metadata grants MIT, and the standard MIT text is well known. We will reproduce the
MIT notice with attribution when using the fixtures.

MIT permits use, copy, modification, and distribution, provided the copyright notice and
permission notice are included. It disclaims warranty. There is no copyleft.

Implemented use: four **reference fixtures** are in `tests/fixtures/` with the upstream
commit and MIT notice recorded. No JavaScript code is used.

### 2.6 `kiwi` / `kiwi-schema` (JavaScript and Rust) — MIT

Evidence:

- npm `kiwi-schema@0.5.0`: `"license": "MIT"`.
- crates.io `kiwi-schema@0.2.1`: `license = "MIT"`, author Evan Wallace.

The Rust crate is a candidate runtime dependency (ADR-0004). MIT is compatible with the
project license. Attribution goes in `THIRD_PARTY_LICENSES`.

## 5. Attribution plan

Files to ship with every binary or release archive:

- `LICENSE-MIT` and `LICENSE-APACHE` for the project.
- `NOTICE` naming the project and any required attribution.
- `THIRD_PARTY_LICENSES` generated with `cargo-about` or maintained by hand, including:
  - `openfig-core` fixtures (MIT, OpenFig contributors).
  - `egui`/`eframe` and other Rust dependencies.
  - Any icon set, font, or asset that is bundled.
- In-app **About** screen with the same notices and a link to the repository.

Do not bundle fonts, icon sets, or sample designs whose license is unclear. The app uses
system fonts for UI and preserves document fonts by name; it does not redistribute font
files.

## 6. Copy vs. port vs. reimplement

| Option | Result | Decision |
|---|---|---|
| Fork the reference converter | Unlicensed code; MPL-derived core; Node runtime | Rejected |
| Port the exporter's parser to Rust | MPL obligations on translated files; large translation effort | Rejected |
| Reimplement from behavior and observed formats | No code reuse; permissive license possible | **Chosen** |
| Use the exporter as a subprocess | Violates pure Rust and offline simplicity | Rejected |

This is a **reimplementation without code reuse**, not a formal clean-room. The same
engineers read upstream source to learn behavior. That is honest to state: a formal
clean-room would separate the specification team from the implementation team and document
that separation. We do not claim that. What we do claim is:

- No source code, tests, comments, or documentation text is copied or translated.
- Format facts come from files we generated or inspected and from public documentation.
- Every dependency is license-checked.
- If a future contribution includes code of uncertain origin, it is rejected until
  provenance is established.

Before 1.0, counsel should review this section and the attribution files. If counsel
requires a stricter process, the code can still be audited: the git history and ADRs record
what was consulted.

## 7. Project license

**Recommended: dual `MIT OR Apache-2.0`.** Recorded in
`docs/DECISIONS/0001-project-license.md`.

Why:

- Compatible with every planned dependency.
- Familiar to Rust users and corporate adopters.
- Apache-2.0 adds an express patent grant; MIT keeps the license short and permissive.
- No copyleft obligation is needed because no MPL code is reused.

Caveat: if any MPL-2.0 code is ever copied or translated, the affected files must remain
MPL-2.0 and the project's licensing story changes. That is a stop-and-reassess event, not a
routine contribution.

## 8. Other legal considerations

- **Trademarks.** "Figma" and "Penpot" are trademarks of their owners. The project name uses
  them nominatively to describe interoperability. Do not use their logos, imply endorsement,
  or name the app in a way likely to confuse. Add a disclaimer to the README and About
  screen: "Not affiliated with or endorsed by Figma or Penpot."
- **Patents.** Reading behavior does not clear patent rights. The format and conversion
  techniques could be covered by patents in some jurisdictions. This is outside an
  engineering assessment; counsel should consider it before commercialization.
- **DMCA / anti-circumvention.** The app converts files the user already has; it does not
  bypass access controls, DRM, or Figma's authentication. Do not add features that fetch
  files from Figma's servers or circumvent export restrictions.
- **Privacy.** No telemetry, no uploads, no accounts. If a future feature adds networking,
  it must be opt-in and documented, and this assessment must be revisited.
- **Contributions.** Use a Developer Certificate of Origin (DCO) or a lightweight CLA that
  confirms the contributor has the right to submit the code and that no unlicensed code was
  copied. Record the choice in `CONTRIBUTING.md` at M1.
- **Export control.** Standard permissive open-source software; no encryption beyond
  general-purpose hashing/compression. Re-check if a cryptography feature is added.
